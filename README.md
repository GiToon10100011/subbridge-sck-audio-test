# sckaudio

macOS에서 재생 중인 소리만 캡처해 WAV 또는 M4A로 저장하는 Swift CLI. ScreenCaptureKit을 쓰고, 영상은 저장하지 않는다.

"브라우저나 OTT 재생 환경에서 시스템 오디오가 실제로 잡히는가"를 확인하려고 만든 **기술 검증용** 최소 구현이다.
DRM을 우회하는 기능은 없다. 막히면 막힌 대로 관찰해서 보여준다.

## 개요

### 주요 기능

- **시스템 전체 또는 앱 단위 캡처** — `--app` 으로 특정 앱의 소리만 고를 수 있다.
- **창 선택기로 캡처 대상 지정** — `--picker` 로 macOS 네이티브 선택기를 띄워 창 하나를 고른다 (macOS 14+). 그 창의 오디오는 이 Mac 의 Edge 에서 창 단위가 아니라 앱(프로세스) 단위로 잡히는 것이 관찰됐다 ([격리 실측 결과](#격리-실측-결과)).
- **오디오만 저장** — 화면 영상은 받는 즉시 버리고 어디에도 쓰지 않는다.
- **WAV(16-bit PCM) / M4A(AAC) 저장**
- **실시간 상태 표시** — 경과 시간, 캡처된 오디오 시간, 피크/RMS(dBFS), 입력 상태(`WAITING` / `ACTIVE` / `SILENT` / `STALLED`)를 0.5초마다 표시한다.
- **종료 요약** — 상태별 누적 시간, 상태 변화 구간 타임라인, 받은 버퍼 수, 최대 피크, 저장된 파일 크기.
- **권한 점검** — 화면 녹화 권한 상태와 권한을 줄 터미널 앱을 알려준다.
- **권한 없이 돌리는 자가 검증** — 합성 신호로 계측과 파일 쓰기 경로를 확인한다 (`selftest`).

### 명령 한눈에 보기

| 명령 | 하는 일 |
|---|---|
| `sckaudio check [--request]` | 화면 녹화 권한 상태 확인. `--request` 는 권한 요청 창을 띄운다 |
| `sckaudio list` | 실행 중인 앱 목록 (`--app` 에 쓸 이름 · bundle id · pid) |
| `sckaudio record [옵션]` | 오디오 캡처 → 파일 저장. Ctrl-C 로 종료 |
| `sckaudio selftest` | 권한 없이 계측기 · WAV/M4A 쓰기 경로를 합성 신호로 검증 |

## 프로젝트 상태

**시스템 전체 캡처로 실제 소리가 파일에 담기는 것은 확인했다. 창 선택기(`--picker`)로 고른 창의 오디오는 창 단위가 아니라 그 창이 속한 앱(프로세스) 단위로 캡처되는 것이 관찰됐다 (Edge, 이 Mac 한정, 2회 재현).**

| 항목 | 상태 | 근거 |
|---|---|---|
| 빌드 (debug · release) | ✅ | 2026-11-03 `swift build -c release` 성공 |
| `selftest` | ✅ 16/16 | WAV · M4A 각 8항목 (2026-11-03 재실행) |
| 권한 | ✅ 허용됨 (cmux) | `sckaudio check` (2026-11-03) |
| 캡처 시작, 버퍼 수신, 포맷 | ✅ | 초당 약 50개 버퍼, `48000Hz 2ch Float32 non-interleaved` (2026-11-02) |
| WAV · M4A 파일 생성 | ✅ | `afinfo` 로 길이 확인 (4.06초 / 3.02초) |
| `-3801` 권한 거부 안내 | ✅ | 실제 시스템 응답으로 확인 |
| 시스템 전체 캡처로 실제 소리가 담기는지 | ✅ | 2026-11-03 `record -d 10` 중 효과음 2개가 `ACTIVE` 로 잡혔고 재생 로그 시각과 일치. 저장된 WAV 재생(`afplay`)은 종료 코드 0이며, 실제 청취는 사용자 확인 대상 |
| 선택기(`--picker`) UI 표시, 단일 창 선택, 필터 수신 | ✅ | 번들 없는 CLI 에서 동작 (2026-11-03, macOS 26.6.2) |
| 선택 취소 · 선택 대기 중 Ctrl-C | ✅ | 둘 다 종료 코드 3, 파일 없음, 메시지로 구분 |
| 상태 타임라인 출력 | ✅ | 실제 캡처 출력에서 확인 |
| **창 선택 필터의 오디오 범위 (창 / 앱 / 시스템)** | ✅ 앱(프로세스) 단위로 관찰 | 같은 프로세스의 다른 창 소리가 섞이고, 다른 프로세스 소리는 안 섞임. 2회 재현. [격리 실측 결과](#격리-실측-결과) |
| 앱 단위 필터(`--app`)로 소리 유입 | ✅ | Edge pid 1492 의 소리는 잡히고 다른 프로세스(`afplay`)의 소리는 안 잡힘 (2026-11-03) |
| 브라우저(Edge, YouTube) 소리 | ✅ | 시스템 전체 · 앱 단위 · 선택기에서 모두 잡힘 (2026-11-03) |
| OTT 재생 중 오디오 | ❓ 미실행 | |
| 창 B 를 고른 교환 캡처 | ❓ 미실행 | 창 A 에 한정된 특성인지는 배제하지 못함 |

격리 실험의 구체적인 수치와 조건은 [격리 실측 결과](#격리-실측-결과)에 있다.
짧은 효과음이 간헐적으로 캡처되지 않은 사례가 3건 있었다(원인 미확정, 재생 종료 코드를 기록한 통제 실험 6회는 모두 잡힘).
그래서 격리 실험에는 짧은 효과음 대신 지속되는 소리를 쓰고, 항상 시스템 전체 캡처를 대조군으로 함께 돌렸다.

## 기술 스택

| 구분 | 내용 |
|---|---|
| 언어 | Swift (`swift-tools-version:5.9`, Swift 5 언어 모드) |
| 빌드 | Swift Package Manager, 실행 타깃 `sckaudio` |
| 캡처 | ScreenCaptureKit (`SCStream`, `SCContentFilter`, `SCShareableContent`) |
| 변환 · 저장 | AVFoundation (`AVAudioPCMBuffer`, `AVAudioFile`), CoreMedia |
| 권한 확인 | CoreGraphics (`CGPreflightScreenCaptureAccess`, `CGRequestScreenCaptureAccess`) |

| 외부 의존성 | 없음 |

## 요구 사항

- macOS 13.0 이상 (`Package.swift` 의 최소 배포 대상. `SCStreamConfiguration.capturesAudio` 가 13.0부터다)
- Xcode (또는 Swift 5.9 이상 툴체인과 macOS SDK)
- 화면 녹화 권한 — [권한](#권한) 참고

개발과 검증은 **macOS 26.6.2 · Swift 6.4.2 · Xcode SDK 27.2** 에서 했다. macOS 13~15에서는 돌려 보지 않았다.

## 시작하기

### 1. 빌드

```bash
cd ~/sck-audio-probe
swift build -c release
```

산출물은 `.build/release/sckaudio` 이다. 이후 예시는 아래 변수를 쓴다.

```bash
BIN=.build/release/sckaudio
```

### 2. 권한 없이 동작 확인

```bash
$BIN selftest
```

마지막 줄이 `selftest 통과` 이면 계측과 파일 쓰기 경로는 정상이다. 권한이 필요 없다.

### 3. 권한 확인

```bash
$BIN check
```

```
macOS 26.6.2
실행 호스트(권한을 줄 앱으로 추정): com.cmuxterm.app
화면 녹화 권한: 허용됨
```

`없음` 이면 [권한](#권한)의 설정 순서를 따른다.

### 4. 첫 캡처

소리가 나는 상태에서 10초간 시스템 전체를 캡처한다.

```bash
$BIN record -d 10
```

현재 디렉터리에 `capture-<yyyyMMdd-HHmmss>.wav` 가 생긴다.

## 사용법

### record 옵션

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `--app <이름\|bundle id\|pid>` | 이 앱의 오디오만 캡처. 여러 번 지정 가능 | 시스템 전체 |
| `--out`, `-o <경로>` | 출력 파일. 확장자는 `.wav` 또는 `.m4a` | `./capture-<시각>.wav` |
| `--format wav\|m4a` | 파일 형식. `-o` 확장자와 다르면 오류 | `wav` |
| `--duration`, `-d <초>` | 지정 시간 뒤 자동 종료 | Ctrl-C 로 종료 |
| `--rate <Hz>` | 샘플레이트 | `48000` |
| `--channels 1\|2` | 채널 수 | `2` |
| `--include-self` | 이 프로세스의 오디오도 포함 | 제외 |
| `--picker` | macOS 선택기(단일 창)를 띄워 고른 창으로 캡처. macOS 14 이상, `--app` 과 함께 쓸 수 없다 | 사용 안 함 |

- `--app` 은 **pid 숫자 일치**, **bundle id 정확히 일치**, **앱 이름 부분 일치**(대소문자 무시)로 찾고, 일치하는 프로세스를 모두 포함한다.
  브라우저처럼 이름이 비슷한 헬퍼가 여럿이면 여러 개가 잡힐 수 있으니 시작 줄의 `대상:` 을 확인한다.
- 같은 이름의 출력 파일이 있으면 덮어쓰지 않고 중단한다.
- WAV 는 16-bit PCM, M4A 는 AAC (채널당 64 kbps) 이다.
- `--picker` 는 **선택이 끝나야 캡처가 시작**된다. 선택기에서 취소하거나 선택을 기다리는 중 Ctrl-C 를 누르면 캡처 없이 종료 코드 `3` 으로 끝나며, 두 경우는 출력 메시지로 구분된다.
- `--picker` 는 선택 직후 선택 정보를 출력한다: 스타일, 영역, 그리고 (macOS 15.2 이상) 포함된 창의 제목 · 소유 앱 · `windowID`. 창 제목은 선택 시점의 **활성 탭 제목**이라 같은 창도 선택할 때마다 달라질 수 있으니, 창은 `windowID` 로 구분한다.
- 캡처가 시작된 뒤에는 선택을 바꾸지 못하게 고정한다 (`allowsChangingSelectedContent = false`).

### 예시

```bash
$BIN list                                        # 앱 이름 · bundle id · pid 확인
$BIN record                                      # 시스템 전체, Ctrl-C 로 종료
$BIN record -d 30 -o ~/Desktop/test.m4a          # 30초, M4A
$BIN record --app Safari --format wav            # Safari 소리만
$BIN record --app com.google.Chrome -d 20        # bundle id 로 지정
$BIN record --app 12345 -d 20                    # pid 로 지정
$BIN record --picker -d 60 -o ~/Desktop/pick.wav # 선택기로 창을 고른 뒤 60초 캡처
$BIN record -d 20 --channels 1 --rate 16000      # 모노 16kHz (지원 여부는 아래 참고)
```

### 상태 표시

실행 중 0.5초마다 한 줄이 갱신된다 (stderr).

```
[경과 00:12.5 | 오디오 00:12.4] ACTIVE   peak -12.3 dBFS  rms -24.1 dBFS  max -3.1 dBFS  | 버퍼 1203  48000Hz 2ch Float32 non-interleaved
```

| 필드 | 뜻 |
|---|---|
| 경과 | 캡처 시작 후 실제 시간 |
| 오디오 | 받은 프레임 수 ÷ 샘플레이트. 경과와 크게 벌어지면 버퍼가 빠지고 있다 |
| peak · rms | 직전 0.5초 구간의 레벨 (dBFS) |
| max | 시작 이후 최대 피크 |
| 버퍼 | 지금까지 받은 오디오 버퍼 수 |

| 상태 | 뜻 |
|---|---|
| `WAITING` | 오디오 버퍼가 아직 한 번도 안 왔다 |
| `ACTIVE` | 소리가 들어오는 중 |
| `SILENT` | 버퍼는 오지만 구간 피크가 -70 dBFS 미만이다 |
| `STALLED` | 버퍼가 1.5초 넘게 끊겼다 |

stderr 가 터미널이 아니면(파이프, 리다이렉트) 한 줄씩 1초 간격으로 출력한다.

### 종료 요약과 종료 코드

종료하면 stdout 에 요약이 나온다. 아래 값은 형식을 보여주는 예시이고 실측값이 아니다.

```
── 요약 ──
상태별 시간(초): ACTIVE 8.0 / SILENT 2.0 / STALLED 0.0 / WAITING 0.0
상태 타임라인 (캡처 시작 기준, 0.5초 해상도):
  00:00.0~00:02.0  SILENT   구간 최대 피크 -inf dBFS
  00:02.0~00:10.0  ACTIVE   구간 최대 피크 -3.1 dBFS
받은 버퍼 500개, 프레임 480000 (10.00초 분량), 포맷 48000Hz 2ch Float32 non-interleaved
최대 피크 -3.1 dBFS
파일: /path/to/capture.wav (1920044 bytes)
```

**상태 타임라인**은 같은 상태가 이어진 구간의 시작 · 종료 시각(캡처 시작 기준)과 그 구간의 최대 피크를 보여 준다.
시각은 상태 표시 틱(0.5초)에 맞춘 해상도다. 어느 구간에서 소리가 들어왔는지 읽어 [창 단위 격리 검증](#창-단위-격리-검증)의
S / W / X 구간과 대응시키는 용도다. 중간에 끊기는 콘텐츠(말소리 등)는 `ACTIVE` 와 `SILENT` 가 잘게 번갈아 나올 수 있다.

| 종료 코드 | 의미 |
|---|---|
| `0` | 정상 종료. 전 구간 무음이어도 파일이 만들어졌으면 0이고, 요약에 경고가 붙는다 |
| `1` | 오류 (권한 거부, 대상 앱 없음, 기존 파일 존재 등). `check` 는 권한이 없을 때, `selftest` 는 실패할 때도 1 |
| `2` | `record` 중 오디오 버퍼가 한 번도 도착하지 않음 (파일 없음) |
| `3` | `--picker` 에서 선택기를 취소했거나 선택을 기다리는 중 Ctrl-C 로 중단함 (캡처 없음, 파일 없음) |
| `64` | 명령이나 옵션 형식 오류 (사용법을 함께 출력) |

## 동작 원리

### 디렉터리 구조

```
sck-audio-probe/
├── Package.swift                    SwiftPM 정의 (macOS 13+, 실행 타깃 sckaudio)
├── README.md
└── Sources/sckaudio/
    ├── main.swift                   진입점. CLI.run 호출 후 종료 코드로 exit
    ├── CLI.swift                    인자 파싱, check · list · record, 상태 표시와 요약(StatusReporter)
    ├── AudioCapture.swift           SCStream 래퍼. 샘플 버퍼 → AVAudioPCMBuffer 변환
    ├── ContentPicker.swift          macOS 콘텐츠 선택기(단일 창) 래퍼. 선택 · 취소 · 실패를 한 번만 돌려줌 (macOS 14+)
    ├── AudioFileWriter.swift        AVAudioFile 로 WAV/M4A 쓰기
    ├── LevelMeter.swift             버퍼 수 · 프레임 수 · 피크 · RMS 계측
    └── SelfTest.swift               합성 사인파로 계측 · 파일 쓰기 경로 검증
```

### 데이터 흐름

```
SCShareableContent ──▶ SCDisplay (+ --app 으로 고른 SCRunningApplication)
        │
        ▼
SCContentFilter ──▶ SCStream ── 오디오: 48kHz Float32 / 영상: 2×2 픽셀, 1fps
                       │
                       ├─ .audio ─▶ [sckaudio.audio 큐] CMSampleBuffer ─▶ AVAudioPCMBuffer
                       │                                      ├─▶ LevelMeter.record   (계측)
                       │                                      └─▶ AudioFileWriter.write ─▶ .wav / .m4a
                       └─ .screen ─▶ [sckaudio.video-discard 큐] ─▶ 버림

[sckaudio.control 큐]
   0.5초 타이머 ─▶ StatusReporter.tick ─▶ LevelMeter.snapshot ─▶ stderr 상태 줄
   SIGINT · SIGTERM · --duration 타이머 · didStopWithError ─▶ AsyncStream<StopReason>
        └─▶ 종료 절차: stopCapture → 오디오 큐 비우기 → 파일 닫기 → 요약 출력
```

### 설계 결정

**디스플레이 필터를 쓰고 영상은 버린다.** SDK 헤더에 오디오 전용 스트림이 없다. `SCStream` 은 디스플레이나 윈도우 필터가 필요하므로,
영상은 2×2 픽셀 · 1fps 로 줄이고 `.screen` 출력은 받는 즉시 버린다. `.screen` 출력을 아예 붙이지 않으면 시스템이 프레임 전달 실패 로그를
남길 수 있어서 받아서 버리는 방식을 택했다 (붙이지 않았을 때의 대조 실험은 하지 않았다).

**앱 단위 선택은 `including` 필터다.** `--app` 을 주면 `SCContentFilter(display:including:exceptingWindows:)`, 생략하면
`SCContentFilter(display:excludingApplications: [], exceptingWindows: [])` 를 쓴다.

**오디오 포맷을 가정하지 않는다.** 샘플 버퍼의 `AudioStreamBasicDescription` 에서 포맷을 읽어 `AVAudioPCMBuffer` 로 복사한다.
첫 버퍼가 도착한 뒤에 그 포맷으로 `AVAudioFile` 을 연다(늦은 생성). 그래서 버퍼가 하나도 안 오면 파일도 만들어지지 않고 종료 코드 `2` 가 된다.

**선택기(`--picker`)는 선택이 끝난 뒤에 캡처를 시작한다.** `ContentPicker` 가 `SCContentSharingPicker` 를 단일 창 모드
(`allowedPickerModes = .singleWindow`)로 띄우고, 돌려받은 `SCContentFilter` 를 `AudioCapture.start(filter:)` 에 그대로 넘긴다.
기존 `start(display:apps:)` 는 필터를 만든 뒤 같은 메서드를 호출하므로 시스템 전체 · `--app` 경로는 동작이 같다.
선택기 결과(선택 · 취소 · 실패)는 정확히 한 번만 전달되고, 선택을 기다리는 중 Ctrl-C 는 신호 핸들러가 선택기를 깨워 종료 코드 3 으로 끝낸다.
창 필터에서 `includedApplications` 는 비어 있고 `includedWindows` 만 채워졌다 (2026-11-03 관찰, macOS 26.6.2).
이것이 오디오 범위를 뜻하는지는 헤더에 설명이 없어 실측으로 가렸고, 결과는 [격리 실측 결과](#격리-실측-결과)에 있다 (앱 단위).

**`SCRecordingOutput` 은 쓰지 않는다.** macOS 15의 `SCRecordingOutput` 은 영상을 포함한 녹화용이라 오디오만 저장하는 목적과 맞지 않는다.

**스레드 규칙.**

| 큐 | 하는 일 | 접근하는 상태 |
|---|---|---|
| `sckaudio.audio` (직렬) | 샘플 버퍼 변환, 계측, 파일 쓰기 | `AudioFileWriter` 는 이 큐에서만 쓴다 |
| `sckaudio.video-discard` | 영상 프레임 폐기 | 없음 |
| `sckaudio.control` | 상태 타이머, 신호 · 시간 제한 이벤트 | `LevelMeter` 는 `NSLock` 으로 보호 |

종료 때는 `stopCapture()` 후 `audioQueue.sync {}` 로 큐에 남은 버퍼를 다 쓰고 나서 파일을 닫는다.

## 권한

### 필요한 권한

- **화면 녹화 (TCC "Screen Recording")** — 오디오만 쓰더라도 ScreenCaptureKit 스트림이라 필요하다.
  시스템 설정의 항목 이름은 OS 버전에 따라 "화면 및 시스템 오디오 녹음" 등으로 보인다.
- 마이크 권한은 필요 없다 (마이크 캡처를 쓰지 않는다).
- Info.plist 와 엔타이틀먼트는 필요 없다 (번들 없는 CLI).

### 누구에게 권한을 주나

CLI 자신이 아니라 **실행한 터미널 앱**이 대상이다. `sckaudio check` 가 `__CFBundleIdentifier`(없으면 `TERM_PROGRAM`) 환경 변수로
"권한을 줄 앱"을 **추정**해서 보여준다. 이 Mac 에서는 `com.cmuxterm.app` 이었다.

### 설정 순서

1. `sckaudio check --request` 로 요청 창을 띄우거나, 시스템 설정 > 개인정보 보호 및 보안 > 화면 및 시스템 오디오 녹음 에서 위 터미널 앱을 켠다.
2. `sckaudio check` 를 다시 실행한다. `허용됨` 이면 준비 끝.
3. 계속 `없음` 이거나 `-3801` 이 나오면 터미널 앱을 완전히 종료(Cmd-Q)했다가 다시 실행한다.

이 Mac 에서는 권한을 켠 뒤 **터미널 앱을 재시작하지 않았는데도** 실행 중이던 세션에서 `허용됨` 으로 바뀌었다 (2026-11-02 관찰).
재시작이 항상 필요한 것은 아니지만, 반영되지 않으면 재시작이 일반적인 해결책이다.

macOS 15 이후 화면 녹화 권한을 주기적으로 다시 확인받는 동작이 알려져 있다 (이 프로젝트에서 재현하거나 검증하지는 않았다).
갑자기 `-3801` 이 나오면 설정에서 다시 켠다.

## 테스트

### 자동: `selftest`

```bash
$BIN selftest
```

합성 사인파(440 Hz, 진폭 0.5, 2초, 48 kHz 스테레오 Float32 non-interleaved)를 실제 코드 경로에 통과시키고 WAV · M4A 각각 8항목을 검사한다.

| 검사 | 기준 |
|---|---|
| 계측 버퍼 수 · 프레임 수 | 보낸 값과 일치 |
| 계측 최대 피크 | 0.5 (-6.0 dBFS) ± 0.01 |
| 구간 피크 초기화 | `snapshot(resetWindow:)` 뒤 0 |
| 파일 샘플레이트 · 채널 수 | 48000 · 2 |
| 파일 길이 | WAV 는 정확히 일치, M4A 는 AAC 프라이밍 때문에 ±4096 프레임 허용 |
| 읽어 온 피크 | WAV ±0.01, M4A ±0.1 |

**`selftest` 가 검증하지 못하는 것:** `SCStream` 자체(권한, 앱 필터, 실제 소리). 그것은 아래 수동 절차로 확인한다.

### 수동: 환경별 캡처 확인

**0. 기준 확인 (먼저)**
시스템 출력의 음소거를 풀고 볼륨을 올린다. 소리가 확실히 나는 로컬 파일(음악 앱 등)을 틀고 `record -d 10` 을 실행한다.
`ACTIVE` 로 나오고, 저장된 파일을 재생했을 때 들려야 한다. **이 기준이 통과해야 아래 비교가 의미가 있다.**
이 Mac 에서는 2026-11-03 에 통과했다(효과음 2개가 재생 시각대로 `ACTIVE`). 짧은 효과음은 간헐적으로 놓친 적이 있어(원인 미확정)
비교 실험에는 효과음 대신 **지속되는 소리**를 쓰는 편이 안전하다.

**1. 일반 브라우저 오디오**
1. 브라우저에서 DRM 없는 영상을 재생한다.
2. 시스템 전체: `record -d 15`
3. 앱 단위: `list` 에서 브라우저를 찾아 `record --app <이름> -d 15`
4. 시스템 전체는 `ACTIVE` 인데 앱 단위는 `SILENT`/`WAITING` 이면 소리를 내는 프로세스가 `--app` 대상과 다른 것이다. `list` 의 다른 항목(헬퍼 등)을 시도한다.

**2. OTT**
1. 같은 절차를 OTT 재생 중에 반복한다 (브라우저와 전용 앱을 따로).
2. 결과를 `ACTIVE` / `SILENT` / `WAITING` 중 무엇인지, 요약의 "최대 피크"와 함께 기록한다.
3. 소리가 들리는데 `SILENT` 이면 캡처는 되지만 오디오가 비어 있는 것이다. `WAITING` 이면 버퍼 자체가 안 오는 것이다. 이 도구는 어느 쪽도 우회하지 않는다.

**기록용 표**

| 환경 | 시스템 전체 | 앱 단위 | 최대 피크 | 메모 |
|---|---|---|---|---|
| 로컬 음악 (기준) | | | | |
| 브라우저 (DRM 없음) | | | | |
| 브라우저 (OTT) | | | | |
| OTT 전용 앱 | | | | |

이 표를 채우면 이 방식의 쓸모가 판가름난다.

### 창 단위 격리 검증

`--picker` 로 창을 골랐을 때 오디오가 **그 창만**의 것인지, **그 앱 전체**의 것인지, **시스템 전체**인지 가린다.
창 필터가 영상을 한 창으로 제한한다고 해서 오디오도 격리된다고 가정하지 않는다.

소리 출처를 셋으로 나눈다.

| 기호 | 출처 | 준비 |
|---|---|---|
| S | 선택한 창 | 브라우저 창 A 에서 지속되는 소리(YouTube 등)를 재생할 수 있게 준비 |
| W | 같은 앱의 다른 창 | 창 A 와 **같은 프로세스(pid)** 의 창 B. 지속되는 소리를 재생할 수 있게 준비 |
| X | 다른 앱 | 별도 앱(Safari, 음악 앱 등)에서 지속되는 소리를 재생할 수 있게 준비 |

**사전 조건**
1. 시스템 출력 음소거 해제, 위 "0. 기준 확인" 통과.
2. 창 A 의 소유 프로세스를 정한다. Edge 같은 브라우저는 같은 bundle id 의 메인 프로세스가 여럿일 수 있다(이 Mac 에서는 Edge 가 3개).
   선택 직후 출력되는 `창: ... Microsoft Edge pid <N>, windowID <ID>` 의 pid 가 창 A 의 것이다. W 는 **같은 pid** 의 창이어야 한다.

**절차 (한 번에 약 50초)**
1. `$BIN record --picker -d 50 -o ~/Desktop/iso_picker.wav`
2. 선택기에서 창 A 를 고르고, 출력된 `windowID` 와 pid 를 적어 둔다.
3. 캡처 시작(경과 00:00)을 기준으로 10초씩 한 가지만 재생한다.

| 구간 | 재생할 것 |
|---|---|
| 00:00 ~ 00:10 | 아무것도 재생하지 않음 (기준선) |
| 00:10 ~ 00:20 | S 만 |
| 00:20 ~ 00:30 | W 만 |
| 00:30 ~ 00:40 | X 만 |
| 00:40 ~ 00:50 | 아무것도 재생하지 않음 |

4. 종료 요약의 **상태 타임라인**에서 구간별 `ACTIVE` / `SILENT` 와 구간 최대 피크를 읽는다. 경계는 0.5초 해상도라 구간 가장자리 ±1초는 판정에서 뺀다.

**대조군 (같은 절차, 같은 소리 출처로 반복)**
- 앱 단위: `$BIN record --app <창 A 의 pid> -d 50 -o ~/Desktop/iso_app.wav` — 앱 단위이므로 S, W 는 잡히고 X 는 안 잡혀야 한다.
  이름(`--app "Microsoft Edge"`)이 아니라 **pid** 로 지정한다. 이름은 같은 이름의 모든 프로세스와 헬퍼를 함께 잡는다.
- 시스템 전체: `$BIN record -d 50 -o ~/Desktop/iso_system.wav` — S, W, X 모두 잡혀야 한다.

대조군이 이 기대와 다르면 측정 방법 자체가 맞지 않은 것이므로 선택기 결과를 해석하지 않는다.

**판정표**

| S 구간 | W 구간 | X 구간 | 결론 |
|---|---|---|---|
| 잡힘 | 안 잡힘 | 안 잡힘 | 창 단위 격리 |
| 잡힘 | 잡힘 | 안 잡힘 | 앱 단위 |
| 잡힘 | 잡힘 | 잡힘 | 시스템 전체 |
| 안 잡힘 | - | - | 창 필터로는 오디오가 오지 않음 (별도 조사) |

**주의**
- "안 잡힘"은 **같은 구간을 시스템 전체 대조군이 잡았을 때만** 인정한다. 놓침과 격리를 구분하려는 것이다.
- 창 A 와 창 B 를 바꿔(B 를 선택) 한 번 더 반복해 창 고유 특성을 배제한다.
- 저장된 WAV 를 재생해 귀로도 확인한다.
- 결과는 이 Mac 의 환경(macOS 26.6.2, 출력 장치 USB 오디오)에서의 관찰이다. 다른 OS 버전이나 브라우저로 일반화하지 않는다.
- **캡처를 동시에 돌리지 않는다.** 한 캡처가 도는 중에 다른 `sckaudio` 를 띄우면 도는 스트림이 끊기거나 새 프로세스가 멈춘다 ([문제 해결](#문제-해결) 참고). 대조군은 순차로 돌린다.
- 선택기가 열리면 **안내판을 포함한 다른 앱의 창이 화면 창 목록에서 사라진다.** 고를 창에 대한 안내는 선택기가 열리기 전에 보여 주거나 알림 배너로 보낸다.

### 격리 실측 결과

2026-11-03, macOS 26.6.2, Microsoft Edge (YouTube 영상). 창 A(windowID 101790)와 창 B(windowID 95832)는 모두 **같은 프로세스 pid 1492** 의 창이다.
S 는 창 A, W 는 창 B 의 영상(사람이 재생), X 는 스크립트가 `afplay` 로 자동 재생한 지속음(220 Hz + 330 Hz)이다.

| 캡처 | 고른 대상 | S (창 A) | W (창 B) | X (다른 프로세스) |
|---|---|---|---|---|
| 시스템 전체 (대조군) | - | 잡힘 | 잡힘 | 잡힘 (-18.5 dBFS 고정) |
| 앱 단위 `--app 1492` (대조군) | pid 1492 | 잡힘 | 잡힘 | **안 잡힘** |
| 창 선택기 1회 | 창 A | 잡힘 | **잡힘** | **안 잡힘** |
| 창 선택기 2회 (재현) | 창 A | 잡힘 | **잡힘** | **안 잡힘** |

| 가설 | 예측 | 관찰 |
|---|---|---|
| 창 단위 격리 | W 안 잡힘 | 기각 (W 가 잡힘) |
| 시스템 전체 | X 도 잡힘 | 기각 (X 가 안 잡힘) |
| **앱(프로세스) 단위** | S · W 잡힘, X 안 잡힘 | **일치** (`--app 1492` 와 같은 결과) |

**해석.** 창 선택기로 창 A 만 골랐는데도 같은 Edge 프로세스의 창 B 소리가 함께 캡처됐고, 다른 프로세스의 소리는 캡처되지 않았다.
이 환경에서 창 필터는 영상만 한 창으로 좁히고 **오디오는 그 창이 속한 앱 단위로 캡처한다.**

**근거의 한계.**
- 조건당 1~2회이고, 소리는 사람이 직접 재생해서 전환 시점이 안내보다 2~4초 어긋났다. W 소리가 구간 한가운데에 있어 판정에는 지장이 없었다.
- 판정은 레벨(dBFS)과 시간대로 했고, 어느 창에서 났는지는 사용자의 재생 기록(초록 구간 A, 파랑 구간 B)에 기댄다. 소리의 출처를 신호로 식별하지는 않았다.
- 선택기 캡처 1회차에서 사용자가 파랑 구간 전에 창 A 를 실수로 잠깐 재생했다가 멈췄다. 같은 구간 앞에 1초가량의 토막으로 보이며 W 판정(23~31.5초)에는 영향이 없다.
- 앱 단위 대조군의 기준선(0~10초)에도 창 A 를 실수로 재생한 소리가 있어 그 칸은 무효이고, S · W · X 판정에는 쓰지 않았다.
- **창 B 를 골라 S=B, W=A 로 바꾼 교환 캡처는 하지 못했다.** 창 A 에 한정된 특성일 가능성은 배제하지 못했다 (두 창이 같은 프로세스이므로 가능성은 낮다고 보지만 확인한 것은 아니다).
- Edge(Chromium) 한 종류, macOS 26.6.2 한 버전에서만 관찰했다. Safari 나 다른 OS 버전은 다를 수 있다.

## 문제 해결

### `화면 녹화 권한이 거부되었습니다 (SCStreamError -3801)`

권한이 없는 상태다. [권한](#권한)의 설정 순서를 따른다. `sckaudio check` 가 알려주는 호스트 앱이 설정에 켜져 있는지 확인한다.

### 계속 `SILENT` 이다

버퍼는 오지만 소리가 없다는 뜻이다. 순서대로 확인한다.

1. **시스템 출력이 음소거이거나 볼륨 0 인가?** 이 Mac 에서 음소거(`output muted:true`) 상태로 4초 캡처했을 때 전 구간 `SILENT` 였고, 음소거를 푼 뒤의 같은 방식 시스템 전체 캡처는 소리를 `ACTIVE` 로 잡았다(2026-11-03). 음소거가 원인이었을 가능성이 높지만, 같은 조건에서 음소거만 바꿔 비교한 실험은 아니다.
2. 대상이 실제로 소리를 내고 있는가?
3. `--app` 을 썼다면 그 앱이 소리를 내는 프로세스가 맞는가? 시스템 전체로 같은 소리를 잡아 비교한다.
4. DRM 보호 재생인가? 서비스가 오디오를 막고 있을 수 있다.

### `WAITING` 이 계속되거나 종료 코드가 2다

오디오 버퍼가 한 번도 안 왔다. 권한을 확인하고(`check`), `--app` 대상이 목록에 있는지(`list`) 본다. 이 경우 파일은 만들어지지 않는다.

### `STALLED`

버퍼가 1.5초 넘게 끊겼다. 대상 앱이 종료됐거나 시스템이 스트림을 멈췄을 수 있다. 시스템이 멈췄다면 `스트림이 시스템에 의해 중지됨: ...` 메시지가 함께 나온다.

### `'X' 와 일치하는 앱이 없습니다`

앱을 먼저 실행한 뒤 `sckaudio list` 로 이름 · bundle id · pid 를 확인해 그대로 쓴다.

### `이미 존재하는 파일입니다`

같은 이름의 파일을 덮어쓰지 않는다. `-o` 로 다른 경로를 주거나 기존 파일을 지운다.

### `--format wav 와 출력 파일 확장자가 다릅니다`

`--format` 과 `-o` 의 확장자를 맞춘다. 확장자는 `.wav` 또는 `.m4a` 만 허용한다.

### `--rate` 가 거부된다

헤더에는 기본값 48000만 적혀 있어 지원 값 범위를 확인하지 못했다. 거부되면 48000으로 되돌린다.

### `--picker`: 선택이 취소되었습니다 / 종료 코드 3

선택기에서 취소했거나(`선택이 취소되었습니다`), 선택을 기다리는 중 Ctrl-C 를 눌렀다(`선택 대기 중 Ctrl-C 로 중단했습니다`). 어느 쪽이든 캡처하지 않고 파일도 만들지 않는다. 다시 실행해 창을 고른다.

### `--picker`: 창 선택기를 실행하지 못했습니다

선택기 시작 자체가 실패한 경우다. 메시지 뒤의 시스템 오류를 확인한다. 이 Mac(macOS 26.6.2)에서는 번들이 없는 CLI 에서도 선택기가 정상적으로 떴다.
다른 OS 버전에서는 확인하지 않았다.

### `--picker 는 macOS 14 이상에서만 쓸 수 있습니다`

선택기 API 가 macOS 14.0 부터라서 13 에서는 막혀 있다. 나머지 기능(시스템 전체, `--app`)은 13 에서도 같다.

### 효과음이 간헐적으로 캡처되지 않는다

짧은 효과음이 한두 번 `SILENT` 로 놓친 적이 있다(원인 미확정). 재생 종료 코드를 기록하며 6회 반복한 통제 실험에서는 모두 잡혔다.
검증 목적의 비교에는 짧은 효과음 대신 지속되는 소리를 쓰고, 같은 구간을 시스템 전체 캡처로 함께 확인한다.

### 여러 `sckaudio` 를 동시에 실행하면 멈추거나 끊긴다

2026-11-03 관찰이다. 원인(macOS 동작인지 이 도구의 결함인지)은 확정하지 못했다.

- 두 프로세스를 같은 순간에 시작하면 하나 또는 둘 다 응답 없이 멈췄다 (둘 다 65초 무출력, `list` 두 개 중 하나는 15초 무응답).
- 스트림이 돌고 있을 때 다른 프로세스가 `list` 를 호출하자 그 스트림이 `응용 프로그램 연결이 중단되었기 때문에 스트림에 실패함` 으로 시스템에 의해 중지됐다.
- 한 번에 하나의 `sckaudio` 만 실행한다. 비교 실험도 순차로 돌린다.

### `--picker`: 선택기가 열리면 화면의 다른 안내가 사라진다

선택기가 열린 동안 다른 앱의 창(이 프로젝트의 임시 안내판 포함)이 화면 창 목록에서 사라진다 (창 레벨을 올려도 마찬가지였다). 고를 창은 선택기를 열기 전에 알려 두거나 알림 배너로 보낸다.

## 알려진 한계

- 디스플레이가 하나는 있어야 한다 (첫 번째 디스플레이를 쓴다).
- 채널은 1~2개만 지원한다.
- 앱 단위 필터는 그 앱이 낸 소리만 잡는다. 브라우저는 소리를 헬퍼 프로세스가 내는 경우가 있어 `--app` 에 여러 프로세스가 필요할 수 있다 (미검증).
- 실행 중이 아닌 앱은 `--app` 으로 지정할 수 없다.
- macOS 13~15 에서는 검증하지 않았다. 산출물의 최소 버전이 13.0 이고 선택기 코드는 14.0 / 15.2 가용성 가드 뒤에 있다는 것은 빌드로 확인했지만, 실제 구동은 하지 못했다.
- `--picker` 는 단일 창만 고른다. 14.0 ~ 15.1 에서는 선택 대상의 앱 · 창 상세(`includedWindows`)가 제공되지 않아 스타일과 영역만 출력된다.
- `--picker` 의 선택 정보에서 창 제목은 선택 시점의 활성 탭 제목이다. 창 식별에는 `windowID` 를 쓴다.
- 창 선택 필터의 오디오는 이 Mac 의 Edge 에서 **앱(프로세스) 단위로 관찰**됐다 ([격리 실측 결과](#격리-실측-결과)). 창 단위로 격리하려면 이 방식으로는 안 된다. 다른 브라우저 · OS 버전은 미검증이다.
- 한 번에 하나의 `sckaudio` 만 실행해야 한다. 동시 실행 시 스트림이 끊기거나 멈춘 관찰이 있다.
- 짧은 효과음의 간헐적 누락 원인은 확정하지 못했다.
- 대안 경로로 Core Audio 프로세스 탭(`CATapDescription`)이 SDK 헤더에 존재하는 것까지만 확인했다. 권한 모델은 검증하지 않았다. ScreenCaptureKit 결과가 부족할 때 별도로 조사한다.

## 책임 있는 사용

- 이 도구는 DRM이나 콘텐츠 보호를 우회하지 않는다. 보호된 재생에서 오디오가 막혀 있으면 막힌 결과를 그대로 보고한다.
- 캡처한 콘텐츠의 이용은 해당 서비스의 약관과 저작권 법규를 따라야 한다.
- 화면 녹화 권한은 강력한 권한이다. 신뢰하는 터미널 앱에만 부여하고, 검증이 끝나면 설정에서 끈다.
